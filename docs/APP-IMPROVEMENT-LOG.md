## MOTION-PROMPT HUMANIZATION (from the doc — bake into prompt.ts video rules)
The app's motion prompts are timestamp-by-timestamp + over-directed → they read AI. The doc's 11 principles fix this:
4. **Over-directed expressions** → describe what she's REACTING TO, let expression emerge; use sequences (notice → glance → react → look away), not labels ("shocked", "pure disgust", "feigned innocent").
5. **Freeze words cause dead frames** — ban "stares", "pauses", "holds", "frozen", "briefly holds", "hold ~Xs". Use "briefly looks toward… then returns", "expression shifts as…", "continues moving while…".
6. **Portrait framing** — "waist-up / subject fills 50-60%" induces a portrait. Use environmental/anti-portrait: "NOT a portrait, NOT close-up, environmental medium-wide, subject occupies ~40%, off-center, room visible, chest-height, slight downward tilt."
7. **Whip pans** — replace "pans quickly / whip pan" with real phone behavior: "quick handheld pivot, slight overshoot then settles; strong natural motion blur only during the fastest part."
8. **Add the idle-behavior block to every prompt** (blinking, eye saccades, shoulder breathing, weight shifts, relaxed fingers, no robotic symmetry, no frozen pose).
9. **Background alive but secondary** (named independent extras: someone reaching for a beer, a server passing once; nobody staring/performing).
10. **Give hands reasons to move** (turn a coaster, thumb the bottle label, tuck hair) — kills the mannequin pose.
11. **Bystander reactions** = believable double-take (briefly notices → second glance → realizes → looks away), never "stares in surprise".
12. **Secondary motion: keep it to 1-2 cues** (hair + fabric-on-breath). Too many ("belt catches light, neckline shifts…") makes the model focus on clothing over the person.
13. **Reproduce as ONE continuous take**, beats flowing into each other ("still chewing from the previous bite"), not separate shots that reset the pose.

## MORE (Aug 13, from a live $17 Seedance 2.5 test — one long take failed)
14. **Clips need CONTEXT / a beginning.** A flowing one-take started mid-conversation → confusing. Clip 1 must ESTABLISH (she notices someone approach, the exchange starts from the top) + a text-overlay hook sets the premise. Don't drop the viewer into the middle.
15. **Camera moves read cinematic.** Tilts/pans/push-ins (even a "gaze tilt down to the shoes") feel produced. → Default to STATIC amateur phone framing, micro-shake only; make any "reveal" its OWN static clip, not a camera move.
16. **Add the model's ACCENT to spoken delivery.** If she talks, bake a soft regional accent ("soft warm Texas drawl, not theatrical") — the app currently omits accent so she sounds generic. **APP CHANGE:** add an accent/voice-delivery descriptor to `voice` and inject it into every dialogue motionPrompt.
17. **Add location-matched AMBIENT sound.** Prompts only said "room tone, no BGM." → Inject scene-appropriate ambience: bar = murmur/chatter/clinks; outside/ranch = birds, breeze, cicadas, distant animals; diner = utensils/booth noise. **APP CHANGE:** derive ambient from the chosen location and add it to the audio line.
18. **One long take = expensive + fragile** ($17 waste). Prefer 2-3 shorter clips stitched in edit — each cheaper to retry and less drift.

## GPT-IMAGE MODERATION + PROMPT-INTEGRITY (Aug 14 — one-shot nbPrompt rejected as "sensitive")

## SET-DRESSING / PREMISE PROPS (Aug 14 — glam-cleaning skit had a spotless room)
21. **The first-frame prompt carries the SET but never the MESS/props the premise needs.** A "glam girl aggressively cleans up a disaster" skit rendered a perfectly clean, staged room → zero context, the joke dies; she's sweeping nothing. Root cause: the beat is derived from the source video's *motion track* (what the subject does), which never describes set dressing; the continuity block only carries the base location (floors, table, stairs). Image gen then defaults to a pristine staged room. **APP CHANGE:** when the premise implies an action-on-the-environment (clean, cook, tidy, unpack, decorate, fix), the generator must derive and inject a concrete **props/state block** into the first-frame prompt — the visible mess/objects the action operates on (e.g. sweeping → a pile of dirt + dried leaves + spilled potted-plant soil in frame) — and the motion prompt must show that state visibly CHANGING (mess getting dealt with), not just the body moving. Add a premise→props derivation step; flag any "cleaning/cooking/tidying" beat whose first-frame prompt has no mess/prop nouns.

Judgement call flagged: Seedance 2.0's LEAN mode argues against adding any clause, but item 23 is unconditional and the lean finding concerns long stacked NEGATIVE lists, not one positive constraint — revisit if 2.0 rejection rates move.
51. **Item 6 vs item 43 RESOLVED — ITEM 6 WINS AT EMIT, ITEM 43 KEEPS ITS DATA.** This was a genuine design conflict, not a typo: item 43 injects the analyzed source's own framing per beat and `reproduce` mode is meant to be 1:1, but the analyzer is *instructed* (prompt.ts, `framing` field) to write exactly the phrasing item 6 bans. Both rules were live and contradictory — `lintMotionPrompt` flagged the words, then `ensureBeatCameraPhysics` re-injected them AFTER the lint had run, so nothing ever caught it. All 3 live motionPrompts carry `CAMERA(source): medium shot, waist-up, subject fills 50%`. **DECISION:** the analyzer's stored vocabulary is left ALONE (169 formats are already stored with it; re-analysing the library to reword it would cost real money for zero output gain), but nothing emits those words into a prompt any more. `framingToAntiPortrait` translates at the emit boundary, preserving what actually carries fidelity — the source's own numeric subject size, and the shot size, which rides its own token — while dropping the portrait-inducing tokens. Source fidelity is semantically intact; only the phrasing changes. The injector also no longer stacks a second framing when the LLM already wrote the source wording: policing that wording is the LINT's job, not the injector's.
52. **Item 6's NB surface was entirely unlinted — not "partially fixed".** `flagTell` lived only in `lintMotionPrompt`, so `lintNbPrompt` had no portrait check whatsoever. That is why the live `ideations[1].beats[0].nbPrompt` reads "camera at chest height, waist-up framing, subject occupies ~40%" with nothing flagged. **NOW:** `lintNbPrompt` carries the same check, negation-aware and scanning the protected-sentence-stripped body so the identity lock's own wording is never flagged. The ban, the NB check and the emit-time translator all share one `PORTRAIT_FRAMING_TERM` constant so they cannot drift apart.

## ⭐ PHASE 3 — THE FEEDBACK LOOP + CLEANUPS (Aug 28, brief §P1.1)
53. **Item 32 SHIPPED: the app can finally learn.** Evidence it was unbuilt: all 138 live runs sat at `status='draft'`, `GenerationStatusSchema`'s `approved`/`produced` values were written by no code path, and no PATCH/PUT route existed on `/generations`. **NOW:** migration `0004` adds `verdict` / `verdict_note` / `verdict_at` / `verdict_ideation` (nullable, non-destructive — existing rows read as "never judged", which is the truth); `PATCH /generations/:id` takes `{verdict: 'up'|'down'|'shipped', ideationIndex?, note?}` and is idempotent (re-thumbing OVERWRITES, so a double-click cannot inflate counts and the operator can change their mind); thumbs live on the run panel in `GenerateView.tsx`, optimistic with rollback so a slow API never looks like a lost click. The existing `status` column is untouched — pipeline axis and quality axis stay separate, per the locked decision. ⚠️ Verdict columns live OUTSIDE the stored output blob (the blob is written once at generation time; a verdict arrives later), so `GET /generations/:id` merges them onto the response.
54. **Fusion-quality prior in the sampler.** `fitness(F) = (ups + β)/(ups + downs + 2β)`, β=2, folded in as `score² × fitness × laneBias`. β is doing real work: an unjudged format sits at EXACTLY 0.5, so the 82% of the library that has never been drawn is not punished for it — and because 0.5 rescales every weight by the same constant, introducing the prior changes NO relative probability until an actual thumb lands (regression-tested). A single thumbs-down gives 0.4, not 0, so one data point nudges instead of condemning. **Soft weighting only:** fitness is bounded strictly above zero (0 ups / 1000 downs still returns 2/1004), so it can never hard-exclude a format — the library is the asset. Credit is counted BOTH ways a run reaches a format: as a fused source (`sourceFormatIds`) and as the subject of a reproduce/adapt run (`format_id`); counting only the first would drop every non-synthesis thumb on the floor. `shipped` counts as a strong up. Proven by seeded-RNG tests in `tests/feedback-fitness.test.ts` (14 tests), including that a down-voted high scorer still outdraws an unjudged low scorer — feedback nudges, it does not override quality.
55. **CORS was missing PATCH.** `worker/src/http.ts` allowed `GET, POST, PUT, DELETE, OPTIONS`. The browser preflight would have rejected every thumb before it reached the worker — the feedback UI would have looked broken with a green backend. Caught while wiring, not in production.
56. **Tailwind's source scan is now bounded to `src/`.** Tailwind v4 auto-detects sources by walking every non-ignored file in the repo, `.md` and `.json` included. Caught in the act: committing the diagnosis brief added a live `.shrink{flex-shrink:1}` rule to the production stylesheet because the brief quotes item 23's "do NOT slim, shrink, or distort". Prose changes must not be able to alter shipped CSS. Fixed with `@import "tailwindcss" source("./")` in `src/index.css` — note `source(...)` must ride the @import; a standalone `@source` rule is ADDITIVE and leaves the repo-wide scan in place (verified). **Bonus: the CSS bundle dropped 36.9kB → 30.9kB (−16%)** — docs had been contributing ~6kB of utilities nothing renders.
57. **Deleted the `.env.production` trap and made the API host overridable.** It was TRACKED in the repo, set `VITE_PROXY_URL` to the **legacy** `ugc-worker` host, and was read by nothing — pure misdirection for the next reader. `src/config.ts` now reads `import.meta.env.VITE_API_BASE` with the production URL as fallback, so a plain build still cannot target the wrong host, but local dev and a future Cloudflare Pages move can redirect without editing source. Types via a new `src/vite-env.d.ts`.

## ⭐ PHASE 5 — HUMANIZATION: THE ENFORCEMENT GAP (Aug 28, locked decision 1)
58. **The instruction layer for items 4–13 was ALREADY DONE on main — the kickoff's premise was stale.** `worker/src/generate/prompt.ts` carries a complete 12-law HUMANIZATION LAWS block that is *broader* than the one in `worktree-humanize-prompts`: main covers everything the branch had (reaction-not-prescription, freeze words, idle life, bystanders, hands, secondary motion, continuous flow, live background, anti-portrait, static camera) **plus** accent-on-every-spoken-line, location-matched ambient, and the establishing/wardrobe-variety rules the branch lacked. Nothing needed re-implementing from that branch. Mining `git diff main..origin/worktree-humanize-prompts -- worker/src/generate/prompt.ts` confirmed it: 24 insertions, 102 deletions — the branch was a net *removal*. Its only real contribution was framing (a consolidated numbered block), which main already adopted. **Both branches remain never-merge; `feat/human-prompt-engine` is still 🔑 Khian's to delete.**
59. **The real gap was ENFORCEMENT, and it was silent.** The two-layer design (prompt.ts instruction + rules.ts deterministic lint) had drifted apart: law 2 bans nine freeze terms and the lint knew five (`motionless`, `perfectly still`, `freezes in place`, `holds the expression/pose`, subject-`pauses` all shipped unchecked); law 1 bans NAMING an expression and the lint knew six specific labels; law 9's closing "never 'exact/identical composition'" clause was enforced nowhere. Whenever the LLM ignored the instruction — which is the only time enforcement matters — the terms went straight into a paid prompt. Now all three are linted, negation-aware, sharing the existing `flagTell`.
60. **Two deliberate NON-additions, because the laws' own good examples use them.** (a) `"holds the look for a moment, still blinking and breathing, then her eyes drift"` is law 2's APPROVED continuation pattern for a held beat, so bare "holds the look" must stay legal — only the explicitly-named "holds the expression/pose" is flagged. (b) Bare `pauses` would catch "the music/track pauses", which is audio, not a dead frame — so it is scoped to the subject pausing. Also left legal on purpose: evocative-but-physical writing ("her face opens up") and the noun "a heavy-lidded stare", which is house style for the thirst lane. **Laws 5 (hands need a reason) and 8 (live background) stay instruction-only — there is no deterministic signal for "this gesture has a motivation" that would not fire on good prompts.**
61. **Validated with before/after goldens (`tests/humanization-goldens.test.ts`, 27 tests).** A BEFORE slop prompt must trip every law; each newly-enforced term is asserted individually so a regression cannot narrow a rule silently; and the AFTER human prompt must lint to **exactly zero**. The false-positive half is the important half: these lints feed a one-rewrite repair loop on a PAID generation, so a rule that fires on a good prompt burns a Gemini call and can degrade a working prompt. Precedent: the Jul 26 outage was naive substring matching making every Rosalia run fail on her profile's own mandatory negation lines — an unwinnable rewrite loop. Eight house-style patterns the laws deliberately PRODUCE are asserted legal.

## ⭐ §P2 HARDENING (Aug 28)
62. **Byte caps on the paid ingestion path — there were none.** `analyze.ts` gated only on DURATION (90s/60s) with Cloudflare's 100MB request limit as the sole upload backstop, and `fetchVideo` read a resolved CDN URL through a bare unbounded `res.arrayBuffer()`. A worker has ~128MB of memory (so a big file OOMs the isolate mid-run) and every byte then goes to the billable Gemini File API. `worker/src/limits.ts` caps both at 96MB. Uploads are rejected from `File.size` BEFORE being read or paid for. Downloads check `Content-Length` when present but **also count the stream and abort mid-flight** — trusting the header alone is how a "capped" download stays uncapped, and there is a test that streams 3MB behind a `Content-Length: 1024` to prove it. Rejections are 413 with an actionable message, mapped in analyze's catch so they aren't opaque 500s.
63. **Fetch-target guard, with the severity stated honestly.** The brief said "resolvers.ts fetches arbitrary caller-supplied URLs" — **verified and that framing is wrong**: `detectPlatform` parses with `new URL` and matches hostnames exactly or by suffix, so `https://tiktok.com@169.254.169.254/` and `evil.tiktok.com.attacker.com` both fail closed already. The real (small) exposure is the DIRECT url returned by a platform API or HTML scrape, which `fetchVideo` requests with redirects followed. `assertSafeFetchTarget` now refuses non-http(s) schemes and internal addresses there. **Low severity and not dressed up:** a Workers fetch egresses through Cloudflare's network, so loopback/RFC1918 aren't reachable as they'd be from EC2 with a metadata endpoint, and the path needs an authenticated operator. Documented limitation: a Worker can't do DNS, so DNS-rebinding is undetectable at this layer. Tests assert the RFC1918 boundary both ways (172.16–172.31 blocked, 172.32 allowed) — an over-broad regex would silently break real CDNs.
64. **Per-operator daily spend caps (migration `0005`, `worker/src/spend.ts`).** `/analyze` and `/generate` had no rate limiting — only Gemini quota ERROR handling, which fires after the money is gone. Keyed `(operator, day, endpoint)` so one operator's automation can't starve the other and the two endpoints get separate ceilings; default 60/day each, overridable via `DAILY_CAP_ANALYZE` / `DAILY_CAP_GENERATE` in `[vars]`. One atomic UPSERT with `RETURNING`, so concurrent requests can't double-spend a slot. Counted in the ROUTER, and deliberately only on `seg.length === 1` — the internal `/generate/variant` SELF dispatches are excluded, or one generate would consume four slots. **FAILS OPEN by design:** a missing `api_usage` table (i.e. 0005 not yet applied — the state this ships in), a D1 blip, or a typo'd cap var all ALLOW the call and log a warning. This is a spend guard on a two-operator internal tool, not an authorization boundary (`auth.ts` is that, and it fails closed); if the counter breaks, the right outcome is "the paid run still works" not "the app is bricked". A malformed cap var never means a cap of 0.
65. **Bundle split 513KB → app 81KB / react 194KB / vendor 228KB / icons 12KB.** A normal deploy now invalidates 81KB of app code instead of the whole bundle. ⚠️ `manualChunks: { react: ['react', 'react-dom'] }` looks right and **silently under-splits** — the app imports `react-dom/client`, which doesn't match the bare id, so react-dom stayed in the app chunk and the "react" chunk came out at 3.9KB. Split by module PATH instead. Route-level splitting deliberately NOT done: it needs real `React.lazy` boundaries and this is a single tabbed surface where every view is immediately reachable, so it would trade a smaller first load for a spinner on every tab.
66. **Fixed a pre-existing build warning:** the Google Fonts `@import` sat after `@import "tailwindcss"`, which expands into rules, so every build emitted "@import rules must precede all rules". Moved to the top of `src/index.css`.
